XXE & Cookie Forgery Tutorial

A practical step-by-step guide to exploiting XML External Entity vulnerabilities and Play Framework session cookies.

Read Tutorial

Tutorial Overview

This tutorial demonstrates how to exploit a vulnerable Play Framework web server (version 2.1.3) using an XXE (XML External Entity) attack and cookie forgery. The goal is to gain administrator access on the web application and understand the full attack workflow, from reconnaissance to post-exploitation.

Scenario

The target is a web server running on a virtual machine with Play Framework 2.1.3, which provides login functionality via JSON requests. Although the requests are in JSON, the server still processes XML internally, allowing XXE exploitation. The attacker machine runs Kali Linux and hosts a malicious DTD file for Out-of-Band (OOB) data exfiltration.

Vulnerability Explored

The server is vulnerable to CVE-2014-3630, an XXE vulnerability. This allows external entities to be included in XML processing, potentially exposing sensitive information such as `/etc/passwd` and session secrets. Additionally, the Play Framework uses stateless session cookies signed with a secret key, which can be manipulated to gain admin access.

Attack Phases

1. Reconnaissance

  • Used Nmap to identify open ports (22 SSH, 80 HTTP, 3306 MySQL).
  • Used dirb to enumerate directories, identifying the login page.

2. Exploitation

  1. Captured a login request using FoxyProxy + Burp Suite.
  2. Modified the request to XML format and sent it to the server, confirming it processes XML.
  3. Performed an Out-of-Band XXE attack using a malicious DTD hosted on the attacker server. This retrieved sensitive files like `/etc/passwd` and `application.conf`.
  4. Extracted the session cookie secret from `application.conf` and recreated the cookie using a Python script that mimics the Play Framework `Sign` function.
  5. Injected the forged cookie into the browser, gaining administrator access to the web application.

3. Post-Exploitation

  • Used the information from `/etc/passwd` and Metasploit to brute-force SSH login.
  • Successfully logged in as user `pentesterlab` and escalated privileges to root using `sudo su`.

Tools Used

  • Nmap: network scanning and service enumeration.
  • dirb: directory and file discovery.
  • FoxyProxy: browser proxy management.
  • Burp Suite: request interception, modification, and attack injection.
  • Python http.server: hosting the malicious DTD file.
  • Netcat (nc): OOB exfiltration and listening for data.
  • URLDecoder: decoding server responses.
  • Storage Inspector (Firefox): viewing and editing session cookies.
  • Metasploit: brute-force SSH attack with `rockyou.txt`.

Conclusion

This tutorial demonstrates the importance of maintaining up-to-date software and secure default configurations. Vulnerabilities like XXE can expose sensitive data and session secrets, allowing attackers to gain admin access. Understanding attack methodologies and post-exploitation techniques helps strengthen security awareness and proactive defense strategies.
